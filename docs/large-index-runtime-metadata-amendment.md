# Prospective runtime metadata amendment

The first metadata-only Django profile freeze stopped on October 14, 2026, before creating its output or execution directory: the editable `semantic-search-engine` installation exposed two distinct physical metadata directories with the same declared name and version `0.1.0`. One is `.venv/lib/python3.12/site-packages/semantic_search_engine-0.1.0.dist-info`; the other is `src/semantic_search_engine.egg-info`. Their coexistence is recorded as installation provenance. No installation repair, model initialization, document inference, or indexing occurred.

The original `docs/large-index-profile-protocol.md`, preparation packet, source membership, eight queries, nine mutation stages, embeddings, retrieval settings, timing schedules, numerical checks, and cleanup requirements remain frozen. This separate amendment changes only how the Python runtime package inventory represents physical metadata. Commit and independently review the amended runner, core, auditor, tests, and this document before a new metadata freeze. Preserve the failed freeze and its exact committed source bytes.

Runtime package inventory schema 2 groups instances by the PEP 503 canonical distribution name. It records both the number of logical distributions and the number of distinct physical metadata directories. Every instance retains its declared name and exact version, resolved metadata directory, the name and SHA-256 of its sole `METADATA` or `PKG-INFO` file, the nullable SHA-256 of `RECORD`, and the nullable parsed `direct_url.json` plus its physical byte hash. Lists and canonical keys are sorted. The observed main environment has 98 logical distributions and 99 physical metadata instances; those are preparation observations, not performance results.

Distinct directories declaring the same exact name and version are retained separately. Only repeated discoveries resolving to the same physical directory with identical complete instance data may be deduplicated. Conflicting versions, different declared names sharing one canonical name, unsupported origins, ambiguous metadata files, or inconsistent aliases fail the freeze. For the known editable project, an egg-info origin must be the frozen project's `src/semantic_search_engine.egg-info`; its installed direct URL must identify this exact local project with `editable: true`. At least one project instance must carry that editable provenance. A mismatched editable origin is refused.

The native package source hashes, actual loaded module origins, Python executable and paths, project implementation source, and all other runtime guards remain required. The independent auditor must reconstruct the physical metadata inventory without importing producer code and require exact agreement with the new freeze. Every later stage still refuses changed runtime or source bytes; no failed attempt is resumed or overwritten.
