# Returned-template preservation development experiment

Authorized November 11, 2026 by the user's instruction to continue. This is one
new, prospectively frozen development rule after the observed native provider
comparison. It tests preservation of already delivered implementations. It
does not admit missing windows, repair latency, execute source, or change the
coverage/backfill default or release 0.1.5.

## Fixed question and source role

Can one literal returned-template protection restore the known hybrid omission
without losing an individually required implementation against any saved
control? The prior annotation guard cannot prove the motivating transformed
class binding. This experiment avoids dispatch/identity claims: source syntax
can be protected without asserting a runtime call edge or query relevance.

The candidate is `returned_template_v1`, implemented by the terminal guard mode
`returned_template_terminal_v1`. Its only proposal is the complete, exact saved
prior-role response. Its fallback is the complete, exact saved coverage response.
The previous state-write role algorithm, semantic-v1 proposals, retrieval ranks,
model features and scores remain unchanged.

For each already delivered baseline row:

1. Require literal finite JSON, exact inventory identity and physical source
   lines, full canonical definition metadata and source hashes. Bind the
   complete captured module, encoding/raw bytes, original inventory/key map and
   source-bundle identity. Saved and overlay provenance stay typed and exact;
   an overlay buffer hash binds the complete decoded module's UTF-8 text, not a
   differently encoded original file. No corpus module is imported or executed.
2. A valid clipped/partial Python window or other language receives no new
   template protection. Existing prior-role protection remains in its saved
   proposal. A complete canonical Python function or async function is located
   in the full module AST, including decorated and nested lexical names/spans.
3. Walk that function's own lexical body, excluding nested function, class and
   lambda bodies. Match a `Return` whose immediate value is `JoinedStr`, with an
   immediate `FormattedValue` whose immediate value is `Call`. Calls only in
   strings/comments, nested definitions, format specifications, wrappers or
   non-returned templates do not establish this role. A direct formatted call
   with a conversion or format specification still qualifies by its value.
4. Emit literal UTF-8 byte and physical-line witnesses for the complete
   definition, return, template, formatted field and call. Preserve Unicode,
   CRLF and bare-CR bytes. This is a syntactic role, not proof that a branch
   executes, a function generates code, performs mutation or implements a query.
   Ordinary user-message formatters can qualify; join-based generators can fail
   to qualify. Async/generator source follows the same literal AST criterion,
   without any claim about runtime return behavior.
5. Protect the entire original dictionary of each matched row. A full canonical
   Python row with parser/canonical-context uncertainty is also protected, with
   an explicit uncertainty status rather than a positive template match. Such a
   row does not reject an unrelated proposal that retains it exactly. Invalid
   captured source/metadata facts fail closed to complete coverage.

Return a defensive copy of the entire saved proposal only when every protected
row remains present and exactly typed, field-preserving and canonically equal,
including signed zero, source, scores and provenance. Otherwise return exact
complete coverage. The actual full returned operand additionally preserves all
JSON mapping order and original timing/index metadata. No timing normalization,
source stitching, reformatting, rank reordering, packing, new candidate, victim
retry, additional inference or graph construction is permitted. Cancellation
preserves the original exception identity, including `ValueError` subclasses.
