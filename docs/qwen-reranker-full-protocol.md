# Full Qwen reranker retrieval experiment

This prospective experiment compares freshly recomputed dense and hybrid retrieval with the same retrieval methods followed by the local original BF16 `Qwen/Qwen3-Reranker-0.6B`. It changes no production defaults. The experimental resident scorer reuses the reviewed literal-query/source template and final-token yes-minus-no projection in `scripts/prototype_qwen_reranker.py` without changing it.

The complete inventory is 144 unique queries across Flask, Requests, Click, Starlette, Rich, Express, Zod and Koa: 118 present behaviors, 26 scoped absent features, 21 multi-file AND queries and 148 required evidence groups. All five Python repositories and Express/Zod have previously observed retrieval results and are development evidence here. Koa's eight source-authored, independently reviewed queries and exact pinned source were prepared earlier without retrieval inference. Its existing clause-rule experiment was blocked because none of its unchanged queries activated that rule; this is a separate reranker experiment with a new prospective freeze, not an override of the old manifest's no-inference flag. Source-authored freshness does not imply exclusion from model pretraining.

The four conditions are `dense`, `dense_qwen`, `hybrid` and `hybrid_qwen`. Each actual request recomputes one Qwen embedding, retrieves its own top 50 windows, and, for the Qwen conditions, scores every returned window sequentially using the resident reranker. There are three actual passes: 1,728 planned requests and at most 43,200 measured pair forwards. Conditions rotate by query index and repetition index. Primary quality uses the first repetition only; the other repetitions measure warm latency and stability. Neither query vectors nor reranker scores are cached. One fixed synthetic addition query/source pair warms the reranker once and is recorded as one additional forward outside the benchmark. One fixed generic query warms embedding/index setup per repository, also recorded and excluded from latency samples.

Hybrid retrieval retains equal-weight RRF with constant 60 and input depth 50. Reranked order is descending observed yes-minus-no logit difference, then original candidate rank and stable snippet ID. No path, symbol, gold group, label, span, note, split or candidate rank enters the model input: only literal query and literal source text. Every scored pair has at most 8,192 total template/query/source tokens. The reviewed builder clips only complete physical source-line prefixes and records clipping; the delivered context still uses the original candidate source through the unchanged packer, so any unscored source suffix is explicitly distinguishable. The rank signal is not calibrated correctness or absence confidence. No threshold, abstention, H2O, shortlist selection or prompt tuning is fitted.

All conditions use the existing `run_clause_fusion.pack_candidates` adapter and the shipped backend packaging: five ranked anchors, at most two explicit static callees per anchor, at most eight excerpts, 12,000 source characters and 4,096 exact `cl100k_base` tokens in the production compact serialized payload. The internal adapter invokes dense packaging even for an externally obtained hybrid candidate list; the actual retrieval family and score kind are recorded independently. The first ranked window per path/symbol and source-prefix packing remain unchanged. Static dependency expansion may deliver a callee outside the original top 50, so candidate coverage is not automatically a ceiling on delivered coverage; report the origin of recovered evidence. Every returned source excerpt must be an exact physical-line slice of the pinned source snapshot, with verified hash and exact token accounting.

Primary quality requires the entire originally declared executable evidence interval from the pinned file. A matching symbol name alone is insufficient. Enclosing/nested windows may cover a declared interval. Original Python intervals are preserved and sometimes describe a narrower executable branch; JS/TS/Koa labels usually require whole declared bodies. Report repositories and language strata separately, and retain original Python exact-symbol-plus-whole-span metrics as a compatibility diagnostic. The new primary metric must not be directly compared with historical symbol-dependent percentages. Gold is evaluated only after ranking and measured packing. All 26 absent cases remain in the output, including plausible decoys, outside positive accuracy denominators.

Freeze hashes of all original manifests, labels, pinned production source files and extracted windows, actual producer/helper/core modules, the offline packing tokenizer, main environment package closure and exact model/runtime identities before root-owned inference. The scorer uses a separate pinned environment and exact original checkpoint with full byte verification, pinned imported Qwen3 source origin and metadata witnesses. Verification and model load happen once before warm samples. Embeddings stay resident across repositories. Existing valid indexes may seed new owned per-run databases through a read-only SQLite backup; actual refreshed/reused windows and document calls establish whether setup was warm or cold. Koa gets a new index. Setup/index work is reported separately and is not a fresh-install benchmark.

The measured main interval includes actual query embedding, retrieval, authenticated blocking loopback HTTP to the resident scorer when applicable, reranker result ordering, and unchanged packaging. It is a warm **in-process pipeline with a helper HTTP hop**, not latency for the complete production HTTP search endpoint. Separate query embedding, candidate retrieval, reranker round trip, server tokenization, evaluated pair forwards, server scoring and packaging intervals are recorded. Token/hash observation and per-forward logging remain included and are instrumentation overhead; source-content artifact writes, main request ledger writes, source validation and gold scoring occur after the measured interval. No timings are reconstructed from earlier scores. The two GPU processes are serial: main embedding completes before the blocking scorer request, and the single-worker scorer completes before the next request.

Preserve every attempt, failure, startup/cleanup event and actual forward. Content-addressed literal sources are stored once; each fresh candidate list has an order/hash receipt and references its immutable pool. Identical pools may reference the same stored data, but every repeated request actually retrieves and rescores. Report within-pair candidate identity/source mismatches and across-repetition vector/order/score differences without retrying, silently substituting cached pools or selecting favorable samples. Retain all complete evidence gains and regressions, candidate coverage, group coverage, multi-file completion, absent decoys, exact compact tokens and warm median/P95 with explicit sample counts. Report development and fresh Koa separately. A clean scorer stop alone does not mean all 1,728 requests or 43,200 forwards completed: independent audit must reconcile planned schedule, completed attempts and pair ledger.

This experiment does not measure coding correctness, paid-agent token use, broad latency generalization or numerical parity against PyTorch. Any retrieval improvement must survive the frozen full development benchmark and fresh Koa check before a new coding comparison is designed. Original failed and one-selected-case experiments remain unchanged.
