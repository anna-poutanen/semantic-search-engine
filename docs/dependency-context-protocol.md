# Annotated dependency preservation and provider cost

This is the next development experiment after the failed
[fresh attrs study](../results/role-native-holdout-v2-2026-11-03/findings.md).
All existing datasets, including attrs, are observed development evidence.
The released coverage policy and release 0.1.5 stay unchanged. Another coding
comparison remains gated on qualified retrieval improvement.

## Fixed quality rule

Start with the exact saved role-guarded semantic proposal and the original
coverage response. Add source-only edges for direct calls on explicitly
annotated Python parameter receivers. Accept only unambiguous source class and
method definitions, with literal annotation, import/class resolution and call
witnesses. Do not execute annotations or corpus code. Decline unsupported
annotations, ambiguous or rebound bindings, uncertain class dispatch, receiver
escapes and unsupported lexical scopes. An edge describes a declared source
dependency; it does not prove runtime dispatch or query relevance.

When coverage already delivers both the caller and callee as exact full
canonical definitions, and the call and annotation are physically present in
the delivered caller, protect both complete baseline dictionaries. If the
saved parent proposal removes or changes either endpoint, reject the entire
proposal and return exact coverage. Otherwise return the exact saved proposal.
Do not salvage, repack, fetch, stitch, admit another dependency, expand budgets,
or retry another proposal. Use no dataset/query/path/name exceptions or labels.

The graph and guard live under `experiments/dependency_context/`; they do not
change the existing production graph or any old experiment source. New code
imports the pinned original helpers. Old source freezes and all original
failures remain reproducible at their original commits.

## Complete observed sample and gate

Freeze code, tests, this protocol and self-contained inputs before the first
new guard outcome. Inputs contain all 393 historical role decisions plus all
84 saved attrs candidate requests, paired with 954 original control responses.
Source bundles retain all 417 pinned module files across 13 corpora, original
snippet inventories, canonical keys and hashes. Read local corpus files only
to export these exact bytes; never rebuild whole modules from snippet unions.
Keep selector operands separate from evaluator labels.

Make 477 terminal decisions. Score quality on the 393 historical occurrences
and the 28 first-repetition attrs occurrences: 421 occurrences, 215 distinct
dataset/query units. Other attrs repetitions verify decisions and source
stability; they are not additional independent quality samples. Check exact
compact serialization, literal source, provenance, retrieval/model scores and
all caps for every outcome: eight excerpts, 12,000 source characters and 4,096
compact tokens. No new v1 proposal, model, retrieval, index or backfill runs.

Development qualification requires zero individual required-group,
complete-positive or single-file-first-hit loss against **each** of legacy,
coverage and the saved prior-role proposal, plus at least one distinct newly
complete positive multi-file unit against prior-role. Retaining an old gain
against coverage alone is insufficient. Preserve and list all individual
changes, including failures concealed by unchanged aggregate scores. An
independent review must reconstruct quality and exact-operand decisions from
the frozen inputs and source witnesses.

## Provider diagnostic and candidate optimization

CPU replay reconstructs the actual saved NumPy float32 query, clause and window
vectors and historical forward receipts. It verifies exact feature and provider
receipt equality. The replay performs zero model/index/retrieval/network work;
snapshot callbacks and vector reads are explicitly saved-data stubs. These
measurements exclude real inference, SQLite access and source-snapshot work.
Profile attribution can identify Python costs, but cannot establish native
latency or assign all unexplained native time to one component.

The candidate fast provider preserves the original function code/control flow
in isolated function namespaces. Only vector validation uses a proven exact
NumPy float32 fast path; every other representation uses the original validator.
No global monkeypatches, repeat-query feature caches, different model weights,
float16 vector conversion, reduced dimensions or relaxed source checks. Test
malformed numeric types, shapes, non-finite/zero/non-exact float32 vectors,
source changes, cancellation and partial error receipts. Freeze the candidate
before recording paired original/optimized timings and compare exact outputs,
API calls and resident reads. CPU timings remain diagnostics.

## Proven pre-inference skip

An optional certificate can avoid clause inference when coverage has exactly
eight rows and every row is protected by the union of unchanged v1 protection,
the existing role guard and the new pair guard. There is no free excerpt slot;
every possible victim would either be excluded by v1 or force a terminal
fallback to exact coverage. This is a structural equivalence proof, independent
of semantic similarities, query labels or past outcomes. A free slot or an
unprotected victim declines the certificate. Invalid facts cannot issue it.

Test the certificate with invented actual v1 exchanges and arbitrary feature
scores, then verify every issued certificate against the saved observed final
decision. Count certificate checks separately from terminal decisions. It
establishes no speedup until measured inside actual requests, and does not
authorize skipping provenance/snapshot validation or hiding failures.

## Later native and fresh confirmation

Development and CPU diagnostic passes cannot promote the candidate. Freeze a
separate native protocol, actual request implementation, source/runtime/model
bindings and individual quality/latency gates before model measurements. Time
the entire resident search with original query work, actual fresh clause work,
source/vector validation, allocation, guards and any skip checks included.
Count actual forwards, clause texts, document inference and skipped requests.
Do not substitute repeated-query feature-cache hits for new-query performance.
Retain the existing median ceiling of 1.25 times each control and individual
zero-loss gates. Attrs may be used for an observed-corpus replication, and must
be called observed. Reserve another untouched repository for fresh confirmation
after the new rule is frozen. No fresh quality or native speedup is claimed by
this development protocol.
