# Prospective Koa repository holdout — preparation only

**No retrieval or model inference has run.** These eight labels and source proofs
are a prospective input for a future explicitly dispatched experiment. They do
not establish quality, latency, coding correctness or token savings. No new
Express/Zod clause-fusion outputs were inspected during authoring.

The official `koajs/koa` repository is pinned to
`2fecd029c6ce6b79d65158d28a76538f7f6b0378` (package version `3.2.1`) in the ignored
local corpus `.cache/corpora/koa`. Scope is its seven Git-tracked `lib` JavaScript
files, with no additional exclusions. Dependencies, middleware supplied by an
application, tests, documentation and generated output are outside scope. The
unchanged parser/production implementation extracts 175 saved-source windows;
source headers, license provenance, hashes and the full window inventory are
bound in the CPU source audit. Source viability was inspected before these
labels; this is a source-reviewed repository/settings holdout, not a claim that
the source was untouched or absent from model pretraining.

The dataset contains six positive behaviors, including three multi-file AND
cases, one same-file AND case, and two scoped absent behaviors. Query wording
describes local executable behavior without code paths or qualified implementation
names. Cases were chosen from source behavior and not adjusted to activate the
clause splitter. OR alternatives within a group are interchangeable; every AND
group is required for complete-query credit. Each target binds an entire
implemented function/accessor body, its declaration anchor, inclusive physical
line bounds, the exact UTF-8 evidence SHA256 and full source-file SHA256.
Matching names, comments or a partial body earn no credit.

The three multi-file cases concern string-body metadata plus header-only dispatch,
middleware rejection plus sanitized error delivery, and stream recognition plus
assignment lifecycle and pipeline transmission. External Node/package algorithms
are not implied by local delegation calls. The source notes retain the relevant
conditions, including existing content-type handling, writable/unwritten errors,
proxy trust, valid statuses and conditional pipeline error forwarding.

The already fixed rule in [the development protocol](clause-fusion-development.md)
must remain unchanged: literal full query plus at most three distinct eligible
four-word clauses at its predetermined separators, equal RRF `k=60`, depth 50 per
list and globally 50 merged candidates, followed by unchanged symbol deduplication
and dependency packing. Both future conditions share eight excerpts, 12,000
source characters and 4,096 exact compact tokens, with H2O and abstention off.
The Koa labels must not change that rule, settings, prompts, parser or source
membership. Whether these natural texts activate a rule is an observation, not
a reason to substitute or rephrase cases.

After the query texts were authored, the unchanged rule was checked on all eight:
**zero additional clauses** are eligible. Every case is retained. This is a
comparative-probe applicability failure: the current control would receive only
the same full-query list, so this set cannot discriminate clause fusion from
full-query ranking. It is not an extraction or semantic-label failure. No
wording is replaced to force activation, and no inference should be spent on a
fusion comparison without an explicit future protocol decision. The manifest
and source audit retain this separate failed gate prominently.

Before any future inference, a neutral independent source author must review
every positive group's semantic necessity/completeness, both scoped absents,
query neutrality and byte/source provenance. That reviewer owns
`results/koa-clause-preflight-2026-10-13/source-review.json`. A missing review is a
blocking preflight state. Extraction failures are retained in `eligibility_failures`;
an ineligible case cannot silently be replaced, and inference stops pending
explicit protocol review. The current CPU audit has no extraction failures.

Freeze the independently reviewed dataset, manifest, protocol, source audit and
review hashes before results. A separate future driver must explicitly support
this eight-query inventory; the current 30-query Express/Zod development driver
does not automatically consume it. Future reporting must retain every scheduled
attempt, interruption/failure, gain, regression, absent decoy and extra query/model
cost. Primary measures are complete required-group and multi-file evidence
coverage, with all denominators stated. No threshold is fitted to absent cases.
