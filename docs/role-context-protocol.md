## Question and single rule

Can preserving explicit state-writing baseline implementations prevent semantic
similarity from displacing setup, attachment and receiver-specific preparation,
while retaining useful complementary implementations within the existing caps?

`role_state_write_v1` is a terminal filter on the unchanged
`semantic_final_v1` proposal. It does not select another victim, retry a rejected
proposal, add candidates, reweight scores or change a retrieval mode. Return
the entire unchanged proposal only when every protected baseline window remains
an exact dictionary with the same scalar types, field presence, literal source,
identity and saved/buffer provenance. Otherwise return an exact defensive copy
of the original coverage response, including its original diagnostics. One
forbidden removal rejects a two-exchange proposal as a whole.

For each delivered baseline row:

- Require valid literal source/hash/physical lines and an available canonical
  definition key matching path and symbol. The delivered interval must exactly
  equal that definition's complete interval. Missing, invalid, clipped, partial
  or nonmatching definition evidence protects the row.
- For a complete Python definition, parse a dedented analysis copy with the
  running pinned Python AST. Require one top-level function or async function;
  other contexts remain protected. Protect if any attribute or subscript node
  has a store or delete context, including nested and destructuring targets.
- For complete JavaScript/TypeScript/TSX definitions, use the existing pinned
  tree-sitter wheels on the literal source directly. Protect explicit member or
  subscript writes in assignments, updates, deletions or destructuring targets,
  and initialized class fields. Clean top-level syntax must establish one complete
  function, class, function-valued declaration or expression under the fixed
  source-defined context check. Ambiguous body/field fragments stay protected.
  Do not repair grammar errors or add artificial enclosing wrappers to make a
  snippet parse.
- Unsupported syntax/language, absent or changed parser dependencies, parse
  errors or uncertainty protect the row. Comments and string contents alone
  are not write syntax. Classification is independent of query wording, scores,
  case identity, labels, repository-specific paths and callable names. File
  extensions select the language grammar.

The source and invented tests define the precise grammar-node treatment before
the first observed guard run. Record source-bound classification facts, parser
identity, protected IDs and removed/changed protected IDs outside the response.
Cancellation must propagate. Inputs must not be mutated.

This is a narrow syntactic preservation guarantee. A window without an explicit
property/index write is not proved pure or unnecessary. Call-only mutation,
reflection, aliases and behavior outside the captured definition can escape the
classification. Conversely, a write to a fresh local object's property may be
overprotected. Those limitations cannot be relaxed after seeing outcomes.
