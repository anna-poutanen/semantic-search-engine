# Complementary windows and definitions: observed development result

The fixed `complementary_v2` selector **fails its quality gate**. It completes one
additional Jinja multi-file behavior, but loses two required groups and one
previously complete dense TanStack behavior against the production coverage
policy. Production stays on `definition_context` plus `coalesce_context`; the
regular [v0.1.5 download](https://github.com/anna-poutanen/semantic-search-engine/releases/tag/v0.1.5)
packages that existing tested policy. The new selector is research-only.

## What was tested

The [prospective protocol](complementary-context-v2-protocol.md), source, tests,
independent auditor, original input/reference manifests and preparation evidence
were committed at `33daf2f9a26cedcc21c2506a3966729783e95215` and pushed before
candidate outcomes. The experiment retains the first two actually ranked windows
per exact definition and admits at most two complementary windows/definitions.
It protects anchors, static dependencies, owners and verified caller/callee
relationships. Its exact fractional lexical utility measures per-clause support;
the final guard checks actual delivered protected source and support after
character/token packing and coalescing. Retrieval scores remain original scalars.

All arms use the same limits: at most eight excerpts, 12,000 source characters
and 4,096 exact compact JSON tokens. Original K24 reranker cases retain only their 24 scored windows;
no unscored tail, synthetic source union, additional model or retrieval call is
introduced. Inactive/no-admission searches coalesce once, invoke one guard on
the actual self reference, and make no lazy reference-factory call. Admitted
plans use one actual coverage-reference factory; CPU replay copies the already
reproduced control and makes no native packing-latency claim.

The matrix contains **393 recorded search cases sharing 201 distinct
dataset/query units**, including 322 positive and 71 absent case occurrences.
TanStack is observed development data here. Repeated retrieval modes and study
rows are not independent trials. All 786 original legacy/coverage responses and
their exact compact payloads reproduce before new outcomes. Original Git
identities, source blobs and 2,948 unfavorable historical references remain
immutable; old rewritten history is explicitly distinguished from current
execution rather than relabeled.

## Result and decision

Against production coverage:

| Observed change | Result |
| --- | --- |
| Jinja bytecode rejection/recompile, dense | Gains group 2 and completes the behavior |
| TanStack optimistic result/promise, dense | Gains group 1; behavior still incomplete |
| TanStack mutation scope/serial continuation, dense | Loses groups 1 and 3; previously complete behavior becomes incomplete |
| Individual single-file first hits | No losses |
| Qualification | **Failed: individual evidence losses are forbidden** |

Both production coverage and the candidate cover 415/522 required group
occurrences and complete 253/322 positive case occurrences across the reused
matrix. Identical aggregate totals conceal the one complete gain and one complete
loss. On the eight dense TanStack multi-file cases, completeness falls from
2/8 with coverage to 1/8 with the candidate. Hybrid TanStack completeness stays
1/8. These are authored development case counts, not general coding accuracy.

Compared with legacy there are no lost groups; the previously established
Starlette/Zod coverage gains are not attributed to this new rule. The fixed
criterion requires no lost individual groups, complete positives or single-file
first hits against **both** controls, plus an additional distinct complete
multi-file behavior over coverage. The Jinja gain satisfies only the incremental
gain requirement. The gate and labels were not changed after outcomes.

Of 393 plans, 129 admit candidates and 119 pass the final guard. The remaining
264 use the actual self-reference fast path. All 393 final outcomes, source
windows, original scalars, canonical identities, literal physical prefixes,
packing/coalescing decisions, guard operands, call counts, individual evidence
scores, strata and summary pass the separate independent auditor. That proves
trace integrity, not qualification. There is no new warm-native, coding-task,
provider-token or generation-model claim.

## Why the implementation disappeared

The [saved-trace diagnosis](../results/complementary-development-v2-2026-10-29/posthoc-diagnosis.md)
is explicitly post hoc. `Mutation.execute` was already raw rank 11, remained in
the candidate portfolio and selected backfill pool, and contains both missing
spans. It was not lost upstream or clipped by either budget. Coverage appends it
as the eighth row after removing contained rows. The new plan admits
`MutationObserver.reset` at raw rank 45; re-backfilling an earlier evicted window
then fills the surviving slots before `execute` is reached. All eight delivered
candidate windows are untruncated, using only 2,561 characters and 1,518 tokens.

The guard protects a subset of the actual coverage result. `execute` is outside
that protected subset. A rare comment term, `another`, raises measured lexical
aspect support in `reset`, so the guard accepts the proposal despite the lost
behavior. Word overlap and static neighborhoods do not prove task completeness.

The accepted Jinja gain also replaces unprotected coverage source: only six of
eight original coverage rows remain fully covered, versus seven of eight in the
TanStack loss. Requiring preservation of all prior source would reject both
observed proposals. This property check is not a newly evaluated selector or a
successful repair. A follow-up needs a better measure of complementary task
relevance and must validate the actual post-backfill context. No stop word,
threshold, gate or query was tuned to hide this failure.

## Validation and reserved fresh corpus

Before the final review corrections, the project-wide Python suite passed
3,667 tests with 10 skipped. The final corrected selector, actual toy backend/MCP,
replay, independent auditor and input boundary passed **125 focused tests**,
including an invented 393-case independent roundtrip. The final preparation-file
binding addition passed the 22 replay tests again. The
[pre-freeze review](../results/complementary-preparation-2026-10-29/pre-freeze-review.md)
records the three corrected edge cases and exact byte identities. GitHub runs
the full final source on the committed freeze: **3,680 passed, 10 skipped**,
plus passing editor/helper checks and the installed CLI smoke. The
[CI receipt](../results/complementary-validation-2026-10-29/ci-freeze-summary.json)
keeps that later final-source run separate from the earlier local snapshot.

A separately source-authored attrs 25.3.0 set was committed at
`c9a3184ce3b6945c3a3be1d06bef3ef61896a29a`: 14 queries (eight multi-file, four
single-file, two scoped absences), 35 required groups, 40 qualified alternatives,
and 204 literal windows/202 definitions across 19 supported source files. Its
41 invented validator tests and independent source review pass. The author's
draft predates a later accidental rule-detail handoff; that disclosure and the
unchanged draft hash are retained. The rule designer, replay runner and selector's
code reviewer remain blinded to the reserved bodies. **No retrieval, indexing or model run was
performed on attrs.** The failed development gate leaves this corpus unqueried;
source review is not a fresh retrieval-quality result.
