# Complementary-window native validation

This protocol is prospective. No TanStack query-core retrieval, inference,
rankings, returned contexts or rule activation may be inspected before the
implementation, candidate, labels, source-only reviews and native plan are
committed unchanged. Syntax extraction and independent source review are allowed.
The source author and reviewer disclose their exposure in the reviewed artifacts.
This is repository-level evaluation independence, not model-pretraining isolation.

The fresh source is `@tanstack/query-core@5.90.5`, commit
`ecdf96296b1dfcee617a5a5b9afdf2a42ad436ba`, all supported saved production files
under `packages/query-core/src`. The sole exclusion is the package's own published
source exclusion, `packages/query-core/src/__tests__/**`. The
[author review](window-holdout-source-review.md), independent review and complete
source-only canonical window/definition inventory freeze membership, bytes,
parser identities, gold spans, executable statements, upstream test bodies read,
scoped absence judgments, excluded files and license notices before outcomes.

There are eight multi-file positives, four single-file controls and two scoped
absences, with 33 required groups and 43 source-equivalent target alternatives.
For this authored dataset, credit requires an actual returned excerpt matching
one alternative's qualified symbol and containing its entire physical evidence
interval with exact pinned bytes/hash. OR alternatives enumerate valid extracted
ancestor/nested definitions for the same required source fact; all groups are
AND requirements. Do not credit a name or an unreturned full window. Historical
development datasets keep their original path/full-interval scoring. Report the
criterion difference and each dataset separately; do not pool unlike samples.

Only a candidate qualified by the separately frozen
[development protocol](window-development-protocol.md) can advance. Qualification
must retain every full group, complete positive and single-file first hit from
both the legacy production selector and the previous coverage/backfill research
control, then add at least one distinct complete query over that research
control. Its two previously observed gains cannot be counted as new gains. If no
candidate qualifies, stop before fresh inference and retain all development
failures. Choose exactly one qualified candidate and record the reason before
observing any fresh ranking. Never choose between candidates on this holdout.

Three arms are fixed together: `legacy`, `coverage_control`, and the chosen new
candidate (`connected_union`, `guarded_continuation` or
`guarded_connected_union`). Dense and hybrid are
separate retrieval modes. Use the same resident pinned Qwen3-Embedding-0.6B model,
unchanged 160/40 extraction/indexed snippets and vector-cache policy, raw depth
50, static graph and query text. All arms retain eight excerpts, 12,000 actual
source characters and 4,096 exact compact JSON `cl100k_base` tokens. Dependencies
stay enabled. No extra query/model call, rescoring, new embedding, larger context,
clause retrieval or query rewriting is introduced by assembly.

Connected union is formed from at most two overlapping or adjacent retrieved
windows of the same exact AST definition, at its first representative's original
rank with the original dependency allocation. It can enlarge source and clip
other evidence. Guarded continuation first applies the previous coverage control,
then considers at most eight new forward-extension trials, one accepted companion
per delivered retrieval row. It adds only whole physical lines and must preserve
all prior actual source. Both conditions use new ephemeral composite IDs with
truthful full bounds, hashes, member/used-span receipts and score ownership.
Composites are not indexed, embedded or reranked documents. Their score is an
explicit inherited anchor scalar; reranker fields are null. Same display labels
alone never establish identity. Disconnected source, altered overlaps or mismatched
saved/overlay bindings cannot be combined. No ellipses or reformatted code are
inserted. Composite receipts remain outside the strict compact MCP envelope.
Guarded connected union renders both the connected/coalesced proposal and the
same-input coverage-control reference, then accepts only a proposal that contains
every reference source interval with identical provenance. Otherwise it returns
the reference unchanged. The resident backend call includes both actual packing
passes, source checks and guard cost; the lazy reference factory performs no
additional retrieval or embedding. Diagnostic capture retains both actual guard
operands and verifies the reference equals the separately measured control.

Freeze model weight/provenance/config/tokenizer file hashes, model/runtime/parser
versions, source and exclusion inventories, canonical definition map, dataset,
review/validator artifacts, implementation and tests, this protocol, parent raw
development artifacts, candidate, schedule and gate before execution. The native
backend's source-only map must exactly match the preflight map. Require unchanged
committed bindings before claiming one attempt. Preserve execution/plan commit
identities, partial outputs and failure receipts. No overwritten or resumed run;
a repair needs a new named frozen attempt with the preceding evidence retained.

Initialize the model/index and perform an explicit warm-up in each arm/mode
outside measured requests. Rotate all six arm/mode combinations deterministically
for each query and three real repetitions: **252 measured backend searches**, each
with exactly one actual fresh query embedding and no document work. Capture each
embedding vector/hash and verify identical raw rank/score orders across arms and
repetitions. Time the full resident backend call, including source guards,
selection and exact packing; receipt formatting and draining unused diagnostic
iterators happen after the timer. Report setup separately and retain all timings,
per-mode medians/P95, paired differences and activated versus inactive cases.
Avoid concurrent heavy test/audit/model processes during timing. Preserve and
disclose any sleep or execution interruption. These timings exclude HTTP/MCP
transport and do not measure coding completion time or billed/provider tokens.

Raw receipts retain actual ranked pairs, selected/eligible contexts, origins,
definition/ambiguity map, pre-postprocessing budgeted response, consumed and
unconsumed selected/raw candidate streams, final full rows, literal compact text,
tokens, characters, assembly members, inherited score anchors, reference rewrites
and actual guard reference/proposal operands. The independent auditor imports no producer, selector, backend, model
or index. Pinned CPU syntax parsers and tokenizer are allowed. It verifies pinned
sources, all physical bounds and hashes, canonical member identity and continuous
union coverage, ephemeral IDs, score ownership, dependency references, exact
compact tokens, caps, schedules, original/source-only inventories and committed
binding history. It independently scores all OR/AND evidence and every gain/loss.
Guarded continuation must preserve every research-control source span inside one
actual returned row; unchanged IDs may differ only in a justified rewritten
dependency reference. Composite full-window hashes cover their real intended
unions, including any suffix not delivered after budget clipping.

For each retrieval mode, compare the chosen candidate independently with BOTH
controls. The prospective promotion gate requires:

- At least one net new complete multi-file query over `coverage_control`.
- No individually lost full group, complete positive or single-file first hit
  versus either control, including losses on already incomplete queries.
- Every raw row, composite receipt, source, budget and binding audit passes.
- Candidate warm median is at most 1.25 times each control's same-mode median.

Dense is the production default and must pass; hybrid cannot rescue a failed
dense gate. Preserve all gates, inactive/active counts, missing-group stages,
absent-query inventories and individual regressions even on failure. Any
production promotion also needs the ordinary client/schema/cache/cancellation
tests and context-budget sensitivity checks; a single larger-budget experiment
does not establish safety for smaller MCP requests. A failed gate leaves the
production behavior unchanged. No release assets or coding comparison are implied.
Once outcomes are observed, this dataset becomes development evidence; later
tuning or gold repair cannot retain its fresh status.
