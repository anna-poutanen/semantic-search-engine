# Prospective shared-flow allocation development replay

This separately frozen CPU experiment follows the failed
[source-aware allocation study](source-aware-allocation.md). The old structural
rule retrieved and delivered HTTPX's header preparation before allocation evicted
it for an encoder. Both implementations share an explicit constructor caller.
The new rule tests that general source relationship without naming that query,
repository, implementation or evidence interval in the algorithm.

There is one new arm, `shared_flow`, and no automatic production or release
change. The fresh, source-reviewed TanStack Query repository remains unqueried
unless this arm independently passes its development gate and a separate native
plan is committed. This is project evaluation independence, not pretraining
isolation.

## Immutable inputs and historical conditions

Reuse the same **365 observed first-repetition cases sharing 187 dataset/query
units**: 90 Express/Zod language rows; 30 Express, 30 Zod and 28 Jinja native
rows; 144 Qwen development and 15 HTTPX `hybrid_k24_b1` rows; and 28 urllib3
native legacy rows. All are observed development evidence, including former
holdouts. Reused retrieval conditions and queries are not independent trials.

Both original controls remain immutable records in the October21 window ledger:
`legacy` and `coverage_control`. Retain four historical negative arms:
`aspect_fill` and `aspect_balanced` from October26, and `source_graph` and
`source_graph_all` from October27. Their **1,460 original records** are referenced
by path, one-based line number, sorted-key compact UTF-8 JSON record SHA-256,
full-response SHA-256 and exact compact-payload SHA-256. Original large ledgers
and the complete source inventory are not copied or rewritten.

The new `source_parent` proof binds October27's actual freeze/execution
`e34d6f6`, original audited artifacts and auditor source. Existing original Git
identities and rewritten-history disclosure remain intact. Every current freeze
must precede and be an ancestor of its own execution. No replacement source or
commit is attributed to an old result.

Historical negative **outcomes are never reproduced by a producer**. The new
planner deliberately invokes the frozen old pure source-graph planner once as
an internal source-only base helper. Its actual receipt is exposed as
`base_plan`, and the old proposed eligible ordering is discarded. The new
planner then reconstructs the original baseline from original selected rows,
actual dependency rows and their inherited scores. This internal helper call
does not create a newly reported old-condition outcome. Its receipt must match
both independent reconstruction and the exact original October27 receipt for
the same case.

## One fixed source rule

Every condition retains **8 excerpts, 12,000 source characters and 4,096 exact
compact JSON `cl100k_base` tokens**, static dependencies enabled, original
whole-line packing and source-preserving coverage backfill, extraction 160/40,
candidate depth 50 and each original scored order. Qwen's K24 order receives no
unscored tail. Original raw scores, source windows and dependency owners remain
unchanged. No embedding, retrieval, reranking, new indexed source, query rewrite,
source union or new model score is introduced.

The old pure base helper supplies the same literal two-to-four-clause activation,
canonical representative order, original eligible IDs, first five protected
anchors, original dependencies and owners, one-hop graph witnesses, unique
canonical labels and ranked candidate pool. No newly observed output or gold
information enters these base facts. An inactive base plan returns the original
definition-control eligible sequence with its original fallback reason.

For each candidate in the **original raw-rank order** of that same one-hop pool:

1. Find every uniquely resolved direct caller `P` with an existing literal edge
   `P → candidate`. No dynamic receiver, factory, transitive or grandparent
   relationship is inferred. Unknown or ambiguous canonical identities supply
   no edge.
2. Build the candidate's shared-flow keys from `P` and all uniquely resolved
   direct callees of `P`. Record literal witnesses for both the candidate and
   each member. A caller, sibling or other unranked source is never newly
   retrieved or inserted because of this rule.
3. Tentatively protect existing baseline rows matching those keys, in addition
   to the base's original protection and previously accepted flow protection.
   Adding the candidate needs one exchangeable original slot for every candidate
   in the accepted prefix, including the current trial.
4. If that capacity is unavailable, **stop immediately**. Do not skip the stronger
   blocked candidate to admit a lower-ranked one. Retain the blocked trial and
   its witnesses in the receipt, but roll back all of its proposed protection.
   Any already accepted prefix remains valid.
5. Otherwise commit its flow protection and admit it. Stop after two admissions
   or the end of the original candidate pool.

If no candidate is admitted, return the exact original baseline eligible sequence
with `shared_flow_capacity_blocked`. Otherwise evict the latest unprotected
original baseline rows, one per admitted candidate. Order protected baseline
rows first in original order, then the accepted raw-rank prefix, then retained
unprotected baseline rows in original order. The complete selected list and
original origins map stay unchanged; new retrieved rows retain standard
retrieval provenance and their original scalar scores.

Only committed flow keys extend the guard's neighbor keys and protected original
window descriptors. A blocked trial never contributes final guard protection.
The outer receipt `shared_flow_allocation_v1` records the actual base receipt,
each ordered trial, capacity, stop reason, accepted prefix, committed flow keys
and witnesses, exact guard projection and termination. Its `guard_plan` remains
the existing source-guard schema with mode `source_graph`, explicitly marked
`producer_schema=shared_flow_allocation_v1`. It is a projection authored by the
new planner, not a claim that the old planner generated this new allocation.

## Actual postpacking source guard

The existing source guard runs once without code changes. It receives the exact
guard plan carried by the eligible sequence, the actual packed/coalesced proposal
and one lazy same-input `coverage_control` reference. Development can use its
preceding byte-identical control response; any later native run must perform
and time real reference packing without another query embedding or retrieval.

Protect actual reference rows selected by original protected IDs, dependency
provenance, committed neighbor keys, and same-path overlap with protected
original windows. This includes a containing excerpt that absorbed an anchor or
sibling during coalescing. Literal physical source, complete delivered prefixes,
hashes, origins, owner identities, owner survival and editor-buffer provenance
must satisfy the unchanged guard. Rejecting a proposal returns the exact coverage
reference, even if a preexisting reference has an already clipped/coalesced owner;
the new experiment does not rewrite historical controls.

The harness captures **one flow planner, one internal pure base helper, one
reference and one guard call**. It retains their actual receipts and operands,
prepacking/proposal/reference/final source, raw/selected/eligible order, scalar
scores, origins, source/definition keys, full ranked/backfill rows and exact
compact text/hash/tokens. Receipts stay outside public backend/MCP responses.
The planner and guard never receive query IDs, kinds, gold IDs, evidence spans,
benchmark outcomes or scoped feature labels.

## Freeze and independent verification

Before any new candidate outcome, freeze all new source, backend integration
tests, replay/auditor code and adversarial tests, this protocol, parser/tokenizer
runtime, complete source/definition identity, old artifact hashes and original
Git proofs. `graph-fixtures.json` is a hash-bound pointer to October27's complete
source-only graph inventory. Reconstruct and compare the complete graph at
freeze; do not copy that inventory or change the graph extractor.

Freeze recomputes only the **365 original legacy controls and 337 known coverage
controls**. Commit all unchanged source/tests/protocol/plan/pointers/gates before
`--run`. Run repeats those barriers and reproduces **730 full original control
responses and compact payloads** before the first new trace. It binds both
730-row historical-negative manifests but does not run their producers.

Open the new candidate ledger exclusively and stream each completed trace,
flushing it before starting the next. Exceptions close the gzip stream, retain
a readable partial ledger and failure counters, and prohibit resume/overwrite.
Repairs require a new output directory and committed freeze. Only after all
**365 new traces** complete may summary and findings be emitted.

The new independent auditor reuses the unchanged previous independent auditor
to **re-certify historical data**, without rewriting its original receipt or
invoking an old producer. It reports that 730-row parent data audit separately
from the 365 newly verified outcomes. It then independently reconstructs every
shared-flow admission, raw-rank prefix stop, blocked-trial rollback, exact guard
projection and quality change. Maximal physical-prefix and exact compact-token
packing, deterministic containment/backfill and literal guard checks reuse the
previous independent implementations, not producer code.

The only shared production trust boundary is the frozen conservative source
graph extractor and source/parser modules with pinned grammar libraries. Their
complete output and module hashes remain bound. The independent process forbids
new/old planners, selectors, backend, producer, index, model and numerical
runtime imports and network work. Commit its unchanged source and tests before
canonical auditing; preserve failed audit attempts under separate names.

## Quality gate and fresh-data boundary

Report all seven conditions by original study, dataset and retrieval/reranker
condition. A new arm qualifies only with **zero individual full-group losses,
complete-positive losses or single-file first-hit losses against both controls**,
plus at least **one additional distinct complete dataset/query unit beyond
coverage control**. Partial-query group losses count; already known coverage
gains cannot qualify. Historical source scoring retains path plus full physical
evidence interval. Scoped absent queries remain reported but retrieved or
omitted snippets do not prove feature absence.

There is one candidate, so no post-result candidate choice or tie break exists.
Only an independently audited qualifier may proceed to a separately frozen
native TanStack experiment with the original stricter qualified-symbol/source
hash scoring, both controls, one real query embedding per measured request and
native warm timing. No fresh indexing, rule activation, retrieval or model query
is permitted before that new plan is committed. A failed development gate keeps
the fresh repository unobserved and production defaults unchanged. No release
or coding comparison follows automatically, and this CPU replay establishes
neither native latency, coding correctness, billed token saving nor generalization.
