# Dependency preservation and provider validation

The annotated-receiver guard **fails the development quality gate**. It retains
all 477 saved prior-role responses exactly, recognizes no already delivered
caller/callee pair, and adds no complete multi-file behavior. The known attrs
hybrid formatter loss against coverage remains. Independent integrity auditing
passes; that does not qualify the selector for production or another holdout.

A separate exact float32 validation optimization reduces saved-vector provider
CPU-call medians from **82.2 to 15.8 ms** for dense and **84.3 to 18.2 ms** for
hybrid. Every measured feature, provider receipt and executing replay call count
matches. These are CPU diagnostics, excluding real inference, SQLite, source
scans and other native request costs. They establish no native search speedup.
Production and release **0.1.5 remain on coverage**.

## What was frozen and evaluated

The [original protocol](../../docs/dependency-context-protocol.md) starts with
the exact saved role-guarded proposal and coverage response. A source-only Python
resolver follows direct calls on explicitly annotated parameter receivers. When
coverage already delivers both endpoints as complete, canonical definitions,
the guard protects their whole original row dictionaries. A changed protected
endpoint rejects the whole proposal. This filter retrieves or admits nothing,
does no repacking, and returns one exact full saved operand.

Source freeze `82ad69cccfcf41acfbd97962c406861043b23c44` and complete input freeze
`8b17573decb0e1ae306c3eb375d4fa0a1b7d1fa3` were committed and pushed before the
first new guard outcome or paired optimized measurement. Inputs contain all 393
historical decisions and all 84 saved attrs candidate requests: **477 decisions,
954 legacy/coverage control occurrences, and 417 original source files across
13 codebases**. All data, including attrs, is observed development evidence.
The selector receives source and operands without evaluator labels.

Quality uses 393 historical occurrences plus the first repetition of 28 attrs
occurrences: **421 occurrences / 215 distinct dataset-query units**. The other
56 attrs repetitions check integrity, not independent quality. The sample has
346 positive occurrences, 130 multi-file positives, 216 single-file positives
and 592 required groups. Historical subsets overlap; these counts are not
421 independent new tasks. Limits remain eight excerpts, 12,000 source
characters and 4,096 actual compact tokens.

The unchanged gate requires zero individual group, complete-positive and
single-file-first-hit losses against **each of legacy, coverage and prior-role**,
plus a distinct newly complete multi-file positive versus prior-role. Retaining
the previous Jinja gain against coverage cannot qualify this follow-up.

These aggregates do not pass the individual gate. The new guard has no loss
against legacy or prior-role, but still loses required **group 4** and a complete
positive against coverage for
`attrs_optional_context_converter_and_generated_arguments / hybrid`.
There are **zero distinct incremental complete multi-file gains over prior-role**.
All 477 saved proposals are accepted unchanged; there are zero protected delivered
pairs, zero guard fallbacks and zero changed responses versus prior-role.

Attrs first-repetition multi-file completion is dense **3/8** versus coverage's
**2/8**, and hybrid **3/8** versus coverage's **3/8**. Both values are inherited
from prior-role. Hybrid trades one complete gain for one complete loss; its
unchanged aggregate conceals the formatter regression.

The resolver accepts 32 annotation/call witnesses representing 26 distinct
caller-to-callee source edges across the pinned Jinja, Click and Rich bundles,
but none forms a qualifying pair in a delivered coverage
response. Attrs accepts zero edges. The motivating caller
`_setattr_with_converter` literally annotates `converter: Converter` and calls
`converter._fmt_converter_call(...)`. However, the module reassigns `Converter`
through `_add_repr`, `_add_eq` and `_add_hash` at `_make.py:2918–2920`. The
resolver does not prove the return identity of those transformations and declines
the binding. Passing the receiver to another helper also exceeds its initial
scope. This does not prove that the transformations actually replace the class.
The [source diagnosis](source-diagnosis.md) preserves the exact witnesses and
decline reasons without adding repository or helper-name exceptions.

The prior native traces locate two different selection failures. Hybrid
retrieved the formatter at rank 8 and delivered its required span at coverage
rank 8 before the prior proposal removed it. Dense retrieved it at rank 11 but
coverage already omitted it. A terminal protection filter cannot admit a
definition that coverage never delivered. This study rebuilds no retrieval or
selection proposal and therefore cannot repair that dense omission.

The structural skip union issues **251 certificates**, including 18 attrs
occurrences (six per original repetition). They establish conditional delivered
context equivalence, not actual skipped inference. The implementation has not
been wired into executing requests. The independent audit explicitly lists
**18 timing-only comparison exceptions**, with both original timing dictionaries,
full response hashes and identical compact hashes; it rewrites no saved response.

## Provider CPU comparison

The [paired replay](../dependency-provider-cpu-2026-11-09/paired/summary.json)
uses all 84 original saved attrs candidate records in archive order. There are
78 active records and six actual adapter bypasses. Each record has three CPU
repetitions, alternating original/fast order by record and repetition: **468
timed active calls** in total, and 36 bypass passes with no provider-call timer.
The saved native repetitions are reused inputs, not fresh queries or forwards.

| Mode | Active saved records | Timed calls per implementation | Original median | Fast median |
| --- | ---: | ---: | ---: | ---: |
| Dense | 39 | 117 | 82.168 ms | 15.773 ms |
| Hybrid | 39 | 117 | 84.347 ms | 18.161 ms |

Each implementation sees the same source-bound, read-only NumPy float32 query,
clause and full-window arrays. Every full feature structure, provider receipt,
API/read count and snapshot-callback count matches exactly. All 84 identities
are retained, including bypasses. The candidate and its tests remain byte-bound
to the original `8b17573...` freeze; execution is `9e0d00d...`.

The [separate CPU artifact review](../dependency-provider-cpu-2026-11-09/independent-review.json)
uses standard-library parsing, hashing, Git checks and arithmetic without
importing or rerunning the producer. It verifies all 84 original identities,
252 alternating-order pairs, 504 implementation slots, saved feature/receipt
digests, counters, medians and fixed diagnostic selections. Its limits are
explicit: digests do not reconstruct omitted runtime values, and the recorded
clocks/counters plus inspected stub boundaries are not a separate hardware trace.

The fast path accepts only an exact native NumPy float32 array of shape `(1024,)`,
snapshots it privately, checks finite/nonzero values and returns identical Python
floats. Other representations and malformed values use the unchanged validator,
including its errors. Original provider/feature function code objects run in
private copied namespaces. There are no global patches, relaxed provenance
checks, different weights, reduced precision or repeated-query feature caches.

The [original-provider diagnostic](../dependency-provider-cpu-2026-11-09/original-profile/summary.json)
uses the fixed first two active requests and first actual bypass per mode in the
first saved repetition. Its four active uninstrumented medians are 78.2–86.0 ms.
Under cProfile, `_vector` makes 114–116 calls and accounts for about 94–95% of
the instrumented 376.7–388.1 ms wall time. Repeated component validation and
numeric ABC dispatch are substantial Python costs. Profiling itself has large
overhead; those cumulative timings must not be compared directly with the old
native provider's roughly 340 ms measurement or added to overlapping stages.

Only the provider callable is timed. Imports, both factories, fast clone setup
and fixture reconstruction are outside both timers. Saved callbacks replace
actual source scans, actual SQLite validation/I/O, fresh model/tokenizer API work
and dynamic embedder metadata/package-version generation. Full retrieval,
selection, packing, HTTP/MCP, agent tokens and billing are excluded. Historical
forward receipts are replayed for equivalence; **zero new model, query/document
encoding, SQLite, retrieval or network calls** occur. Runtime is Python 3.12.15,
NumPy 2.5.4, macOS 27.0.1 arm64. No native latency threshold is tested here.

terminal decisions, 954 saved legacy/coverage references, exact compact payloads,

shares the graph resolver for consistency and checks accepted AST witnesses

suite's one existing owned-process cleanup failure. That test and its complete
