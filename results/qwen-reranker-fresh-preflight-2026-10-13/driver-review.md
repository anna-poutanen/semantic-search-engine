# Independent prospective driver review

The final resident/main producer and full protocol pass this CPU-only review of
candidate acquisition, gold isolation, unchanged packaging and timing
provenance. No real reranker outcomes or Koa retrieval results were opened. The
[machine receipt](driver-review.json) binds the reviewed source hashes and the
63 passing focused fake/packer tests. The separate runtime auditor reviews
checkpoint, imported model source, actual pair/forward receipts and cleanup.

The main producer obtains the ordinary full-query top 50 from the backend's
existing dense or equal-weight hybrid retriever. Hybrid retains its ordinary
dense top-one diagnostic. It sends only the literal query and each candidate's
literal source to the resident scorer. The resident rejects additional pair
fields; the model uses the unchanged reviewed builder and final-token scoring
function. Paths, symbols, target spans/groups, notes and splits do not enter the
model input. Source review and normalized gold hashes occur prospectively, but
gold lookup for a measured query occurs after its elapsed interval is captured.

Both baseline and reranked conditions pass their candidate order through the
unchanged `run_clause_fusion.pack_candidates` adapter and shipped backend.
This keeps five anchors, two possible static callees per anchor, eight excerpts,
12,000 source characters and 4,096 exact compact tokens. Actual hybrid retrieval
and the internal dense packaging adapter have separate, truthful metadata;
these annotations do not change the compact source/token payload. Original
Python spans are retained, with the historical exact-symbol metric reported
separately from the new span-based primary metric.

Every condition performs a fresh query embedding and fresh retrieval. The driver
records ordered candidate identity/source hashes, compares baseline and Qwen
within each query/family/repetition pair, and records later observed pool drift.
It retains mismatches rather than replacing an input or retrying an unfavorable
sample. The result audit must verify these receipts; matching algorithms alone
are insufficient to claim identical observed candidate lists.

The elapsed interval includes query embedding, candidate retrieval, observed
pool/vector hashing, authenticated blocking scorer HTTP when applicable, score
ordering and unchanged packaging. Main source-content/pool/request artifact
writes, source verification and gold scoring follow the timestamp. Resident
tokenization/hash/logging overhead is included in the round trip. Model loading,
the fixed synthetic scorer warmup, per-repository indexing and generic embedding
warmup are separately recorded and excluded. This measures a resident in-process
pipeline with a helper HTTP hop; it does not establish latency of the complete
production search endpoint. The loopback client disables proxy environment
routing and redirects and validates the owned loopback URL.

The SQLite seed proof verifies the original database's main-file hash around a
read-only backup into a new owned database. It does not prove sidecars or file
access times were unchanged. Static dependency expansion can deliver source
outside the ranked top 50, so recovered evidence needs an origin assessment.
This review validates the prospective method, not complete scheduled execution,
retrieval improvement, production latency, coding correctness or token savings.
