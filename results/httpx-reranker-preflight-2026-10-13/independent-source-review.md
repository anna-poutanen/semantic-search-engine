# Independent HTTPX source and label review

Reviewer: the batching implementation agent, independently of the HTTPX label author. This review reads pinned source and authored labels only. It reads no HTTPX retrieval rankings and makes zero model, embedding, or retrieval calls. The accompanying `reviewer-receipt.json` binds this note, the reviewer script, the dataset/manifest/preflight inputs, each tracked source file, and all positive gold spans by SHA-256.

The scope is all **23 tracked Python implementation files under `httpx/`** at commit `26d48e0634e6ee9cdc0533996db289ce4b430177` (tag 0.28.1), with no source exclusions. Independent AST and byte checks confirm **12 positive queries, 28 required full-function groups, 3 scoped absents, and 438 eligible source windows**, using 160-line windows and 40-line overlap. Five positives require multiple files, and three require multiple functions in one file. Every group has one complete source function or method whose exact bytes appear in at least one actual source window. This is source eligibility, not a ranking result.

All 28 positive function bodies were read against the requested behaviors and their authored scope notes:

| Query | Required source behavior checked |
|---|---|
| JSON request encoding and headers | `Request.__init__` dispatches to `encode_request`, which selects `encode_json` given the documented no-competing-payload assumption. JSON encoding uses compact separators, UTF-8, `ensure_ascii=False`, and `allow_nan=False`; byte length is computed after encoding. `Request._prepare` merges defaults with `setdefault` and preserves explicitly supplied framing. |
| Stacked content decoding | `Response._get_content_decoder` selects known encoding implementations, ignores unknown names, and composes multiple decoders. `MultiDecoder.__init__` reverses the encoding order; `decode` chains bytes through children; `flush` passes earlier buffered tails through subsequent decoders. External compression algorithms are outside this orchestration scope. |
| Async incremental lines | `Response.aiter_lines` calls the decoder and flushes it at end. `LineDecoder.decode` preserves a trailing CR across chunks and buffers incomplete lines; `flush` releases the remaining buffer and clears trailing-CR state. Charset/decompression are documented prerequisites. |
| Multipart framing | `encode_multipart_data` constructs the stream and returns its headers. `MultipartStream.get_content_length` counts each delimiter, reported field length, and closing delimiter, returning `None` for an unknown-length part. `get_headers` chooses Content-Length or chunked transfer and carries the existing multipart content type. Field probing and boundary construction are explicitly outside the required algorithm. |
| Redirect header safety | `_redirect_headers` removes Authorization across origins except the restricted HTTP-to-HTTPS upgrade, sets the new Host, strips length/transfer framing after a method change to GET, and always removes the old Cookie header. `_same_origin`, `_is_https_redirect`, and `_port_or_default` establish the exact scheme/host/default-port tests. |
| Digest challenge retry | `DigestAuth.auth_flow` returns unless status 401 and a Digest challenge are present, resets nonce count to one, builds credentials, copies response cookies, and yields the authenticated request. Actual cryptographic formatting is delegated and not claimed by this single gold body. |
| Repeated headers | `Headers.get_list` lowercases lookup/stored header names, preserves stored value order, optionally splits commas, and strips whitespace. Quoted-comma parsing is not claimed. |
| Cookie scope and ambiguity | `Cookies.get` applies optional exact domain/path filters, tracks a matched value, raises `CookieConflict` if another match follows a non-null value, and returns the default if no non-null value is found. The source edge case below limits claims for custom null-valued cookie jars. |
| Immutable query updates | `QueryParams.add` copies the map, replaces the selected list with old values plus the new converted value, and returns a new instance. `merge` constructs a new parameter map and merges dictionaries with the new values taking precedence. Neither mutates the original map. |
| Unicode/wire host views | `URL.host` decodes an already normalized host through IDNA only when it starts with `xn--`; `URL.raw_host` returns the stored normalized ASCII bytes. This matches the existing scope notes and does not claim general parsing or normalization. |
| In-process asynchronous application | The complete `ASGITransport.handle_async_request` body includes streamed receive/send callbacks, skips HEAD body bytes, optionally propagates application exceptions, and chooses 500 only when no status was supplied before the exception. It returns local headers/body through `Response`; lifespan/websocket behavior is outside scope. |
| Environment proxies | `BaseClient._get_proxy_map` consults the environment only when no explicit proxy is given and the supplied allow-environment flag is true. `get_environment_proxies` prefixes a missing scheme and returns an empty mount map when any no-proxy entry is `*`. Standard-library platform/environment lookup and later URL-pattern routing are excluded. |

The three absent queries were checked across the full frozen source scope using AST inventories and literal source searches, with manual review of the nearest implementations:

- **Persistent response cache:** response/request `_content` fields and `_decoder` are object-local memoization, not a disk cache with freshness or validator revalidation. `_main.download_response` writes downloaded bytes to the supplied file; it has no later response lookup, freshness decision, or conditional request policy. Cookie storage and redirect comments do not supply the missing behavior. No persistent HTTP response-cache implementation was found in the tracked scope.
- **Server-error backoff retry:** synchronous and asynchronous client loops implement authentication or redirect handling; response returns immediately when neither requests another send. The default transports forward the `retries` option to `httpcore.ConnectionPool`/`AsyncConnectionPool`; they do not inspect response status for exponential backoff or jitter. No such local status-response retry policy was found. Dependency internals and user hooks/transports are excluded.
- **Digest body integrity:** `_build_auth_header` hashes method/path for `A2` and contains an `auth-int` TODO. `_resolve_qop` explicitly raises `NotImplementedError` when `auth-int` is the sole offered mode; an offered `auth` mode is selected separately. It does not implement the requested request-entity hash protection in this scope.

The review accepts the existing gold spans as implementation-location targets with their authored notes. It does not change any labels. A source edge case is recorded: the cookie ambiguity check uses `value is not None`; a custom CookieJar containing null-valued cookies can bypass that guard. Normal `Cookies.set` takes a string value, but this static retrieval experiment must not be described as proving ambiguity rejection for every arbitrary cookie-jar state. Likewise, the Unicode-host target is limited to the stored-host `xn--` prefix branch. Neither qualification is a retrieval-driven label adjustment.
